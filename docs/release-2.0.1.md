# Jellyfin Desktop 2.0.1 — финальный выпуск

Статус: подготовка и финальное ревью; публикация ещё не выполнена.

Windows x64: Windows 10 версии 1903 и новее, Windows 11.

Это финальный выпуск текущего форка. Он остаётся основным клиентом на период
перехода к новой реализации. Дальнейшая разработка этой версии прекращается;
новые функции и плановые обновления не предусмотрены. Новый клиент развивается
отдельно и в этот выпуск не входит.

## Исправления

- Исправлены чёрный экран и следы интерфейса при запуске SyncPlay на паузе.
- Исправлены восстановление размеров окна после fullscreen и обработка
  устаревших отложенных переключений экрана.
- Устранено дорогое смешивание фона меню в программном WebEngine: настройки
  воспроизведения, субтитры, совместный просмотр, медиаданные и контекстные меню.
- Исправлена прокрутка «Параметров клиента», очистка обработчиков и сохранение
  фокуса и недописанных значений при обновлении соседних настроек.
- Списки настроек используют меню внутри интерфейса приложения, включая
  полноэкранный режим. Сохранены типы значений и управление с клавиатуры.
- Включены предыдущие исправления подключения к серверу, быстрого роста памяти
  GPU-композиции WebEngine, ритма отрисовки и задержки закрытия приложения.
- Исправлено сохранение нулевой громкости музыки и видео.
- Исправлены отмена плавной остановки музыки, повторная остановка и запуск
  следующего элемента из обработчика завершения. Старые операции не должны
  останавливать или очищать состояние нового воспроизведения.
- Убрано ненужное ожидание при создании UI видео, из-за которого запуск мог
  продолжиться после остановки или замены видео.
- Ответ на старый диалог ошибки больше не запускает обработку ошибки для
  следующего видео.
- Отмена ожидающего запуска больше не передаётся Web-клиенту как ошибка
  следующего видео. Готовность SyncPlay по-прежнему подтверждается native-плеером.
- Отложенные callbacks смены частоты экрана привязаны к времени жизни плеера
  и текущему файлу; устаревшие callbacks не перенастраивают следующий файл.
- Внешние субтитры загружаются асинхронно: медленный HTTP-ответ не удерживает
  GUI-поток. Добавлены отмена устаревших запросов и очистка старых дорожек.
- Улучшено скрытие известных форм токенов Jellyfin в журнале; полные URL потоков
  больше не выводятся клиентскими обработчиками запуска аудио и видео.

Сохранены SyncPlay с независимыми дорожками, внешнее аудио, Discord Rich Presence,
локальная диагностика и проверка обновлений. Поведение приложения соответствует
проверенной beta 2.0.1-rc.2 (`9530a85`), с дополнительными исправлениями по итогам
финального ревью. Результаты отражаются в списке подготовки релиза.

## Установка

Закройте приложение и запустите `JellyfinMediaPlayer-2.0.1-windows-x64.exe` поверх
текущей установки. MSI/Burn-версия `2.0.10` новее опубликованной 2.0.0 и локальных
beta, включая 2.0.1-rc.2. Имя executable, идентификаторы установки и пути настроек
сохранены.

Обычный portable использует прежние AppData-настройки. Файл-маркер `portable`
рядом с executable включает изолированные data/cache. Diagnostic portable и
symbols предназначены для профилирования; для обычной работы используйте
установщик или стандартный portable.

`SHA256SUMS` содержит контрольные суммы, `build-manifest.json` — закреплённые
зависимости, `release-build.json` — точную сборку и результаты её проверок.

## Известные особенности и границы проверки

Windows по умолчанию использует программный WebEngine; аппаратное декодирование
видео mpv сохраняется. Фон за меню не затемняется, большие формы открываются без
длительного перехода. Таймер Discord может продолжать идти на паузе; позиция
корректируется после seek/resume. Источники, требующие `RequiredHttpHeaders`,
пока не поддерживаются.

Подготовка финального выпуска запрошена 2026-10-20. Оба участника подтвердили
проверку beta 2.0.1-rc.2 без известных оставшихся проблем. Это не заменяет
измерения по полному техническому протоколу. Длительная проверка памяти на итоговом
коде, измерения дрейфа смешанной группы Desktop/Web, накладные расходы диагностики
и установка на чистой Windows остаются технически неквалифицированными.
Исторические неуспешные измерения сохранены; `qt.qualification.qualified`
остаётся `false` до подтверждения требований. Автоматический строгий допуск
к публикации не изменяется; запрос финального выпуска не отменяет проверок.

Server/Web и серверное развёртывание не изменяются. Проверенная контрактная база:
`desktop-handoff-12.2-syncplay.1-r1`, Server/Web 12.2.0. Это закреплённая база
совместимости, а не новое измерение состояния работающего сервера.
